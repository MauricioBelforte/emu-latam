# Log 61: Implementación de flujo WAN manual para P2P propio

**Fecha:** 2026-07-25 04:36
**Tipo:** Feature
**Módulo:** 18-P2P-Propio

## Descripción
Se implementó el flujo WAN manual para el P2P propio sin necesidad de Nakama, bore ni Tailscale. El host publica su IP pública detectada vía STUN, el guest ingresa manualmente la IP:puerto y se conecta vía hole punching directo o relay fallback (nuevo packet type RELAY_REQUEST/RELAY_ACK).

## Archivos Modificados

### p2p-module/src/protocol/types.ts
- **Antes:** 6 packet types (PUNCH a DISCONNECT)
- **Después:** 8 packet types (agregados RELAY_REQUEST=0x07, RELAY_ACK=0x08)

### p2p-module/src/P2PManager.ts
- **Antes:** `handlePacket()` solo manejaba PUNCH, PUNCH_ACK, KEEPALIVE, DISCONNECT
- **Después:** `handlePacket()` maneja RELAY_REQUEST (host registra peer + envía RELAY_ACK), RELAY_ACK (guest recibe confirmación), KEEPALIVE_ACK. Nueva función `waitForRelayAck()` como helper. Nuevo método `startJoinWan()` que hace hole punch y si falla envía RELAY_REQUEST con timeout 8s.

### client/src/main/p2pBridge.ts
- **Antes:** Solo existían `handleP2PHost()`, `handleP2PGuest()`, `handleP2PHostRegisterGuest()`, `handleP2PDisconnect()`
- **Después:** Agregado `handleP2PGuestWan(hostAddress)` que parsea IP:puerto manual, crea PeerCandidate mínimo, llama a `manager.startJoinWan()`, y crea forwarder para RetroArch

### client/src/main/index.ts
- **Antes:** Importaba 4 funciones de p2pBridge
- **Después:** Importa `handleP2PGuestWan` adicional. Nuevo IPC handler `p2p-guest-wan`

### client/src/main/services/ipcChannels.ts
- **Antes:** Sin canal P2P_GUEST_WAN
- **Después:** Agregado `P2P_GUEST_WAN: "p2p-guest-wan"`

### client/src/App.tsx
- **Antes:** Solo vista Nakama-based para P2P fucsia
- **Después:** Agregados estados `p2pWanHostPublic`, `p2pWanGuestInput`, `p2pWanStatus`, `loadingP2pWan`. Handlers `handleP2pHostWan()`, `handleP2pGuestWan()`. UI muestra IP pública del host o input para guest + botones CREAR SALA WAN / CONECTAR.
